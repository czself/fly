# TLE100 任务协议 v1

该协议用于新发射端 `remote/tle100/main.c` 与飞控 `demo02_remote_framed`；原厂字符协议另见第2课。发射端 AT89S52 / 11.0592MHz / 9600 8N1，E49透传，两端频率、地址、信道及 UART 配置须一致。

| 偏移 | 字段 | 值 |
|---|---|---|
| 0、1 | 帧头 | A5 5A |
| 2 | 协议版本 | 01 |
| 3 | 序号 | 每包加1，255回到0 |
| 4 | 命令 | 0心跳、1起飞、2降落、3急停、4校准 |
| 5 | CRC8 | 覆盖前5字节；多项式0x07、初值0、不反射、无末尾异或 |

不按键也发心跳。Timer0等待20ms，加上6字节UART传输约6.25ms，实际周期约26ms；实机需测量。按键用两次扫描确认，F2/F3/F1新按下边沿分别发START/LAND/CALIBRATE，并重复3个新序号包约79ms；按住F4重复STOP，优先级最高，其次LAND、START、CALIBRATE。上电已经按住的START不算新边沿，必须释放后再按。

接收器滑动窗口找6字节帧，坏校验/错误版本/未知命令不更新链路；同一有效链路期间序号仅接受向前1～127步，重复或过旧包不更新。字节间隔>30ms丢掉半帧，300ms没有新有效包则链路无效。断链后第一包可重新建立序号基准，所以两端重启/长时间断线可恢复。CRC用于误码检测，不是密码学验证。

命令包重复不应重复执行任务：START只在空闲且传感器、供电、坐标与任务条件合格时起效；LAND在起飞/悬停时进入降落；STOP清空台架输出；CALIBRATE仅空闲且静止才可执行。第2课只是日志验证器，尚未接入第7课。接入实际飞控后，不能将“某包没收到”直接做无条件空中停桨；须按传感器剩余可用性设计并验证失联降落策略。

飞行期间不发送航向/方向操纵，因此符合自主任务目标。没有完整手动摇杆功能，也没有ACK确认显示；请求重复3次只能改善瞬时丢包，不能证明任务已经被接收执行。验收要同时观察接收日志与任务状态。
