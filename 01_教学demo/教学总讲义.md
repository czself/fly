## 给队员上课：七课教学安排

受众：有基本C语言知识，尚未学习完整飞控。先让每个人说清“这列数从哪里来、单位是什么、什么情况下不能用”，再修改代码。源码、模板和运行命令从 [总入口](README.md) 打开。

建议每课45～60分钟：5分钟提出问题，10分钟讲数据链路，15分钟演示，15分钟队员实验，最后5～10分钟互相解释结果。每组2～3人轮换讲解、操作和记录；记录用 [实验表](docs/LAB_RECORD.md)。今天只有USB与板载器件，先完成第1、2软件解析、第3无PWM、第4模型；到货后再接线执行第5～7课。

| 课 | 问题与演示 | 队员作业 | 验收解释 |
|---|---|---|---|
| 1 | 静止加速度为什么约1g？慢转看gyro、角度、Cube | 命名20列；静置/单轴慢转采集；按四元数绑定Cube | gyro是°/s、姿态是°；yaw缺绝对纠偏，气压高度不是离地高度 |
| 2 | 按键怎样成为命令？先字符，再心跳包 | 无硬件先运行主机测试；到货后烧发射/接收配对，观察UART4 | 字符recent不等于链路；周期心跳、CRC、序号、重复命令各管什么 |
| 3 | 请求油门为什么不能直接驱动？ | 先跑无PWM门控；拆桨后单路长按/释放/超时实验 | 上电按住不触发、长按2s、15%最多3s、急停、看门狗；M5用途不同 |
| 4 | 如何从目标高度生成四路电机需求？ | 模型起飞到0.5m，等超过5s再按KEY1降落；KEY2停止；测试数据失效 | 模式、外环、内环、积分限幅、虚拟混控；模型不是实飞 |
| 5 | 测距成功是否等于测量有效？ | 模块到货后尺测0.2/0.5/0.8m、遮挡、超量程、时效记录 | 传感器参考平面、斜距、NaN、状态9、150ms失效；差分速度有延迟 |
| 6 | 图像变化为什么既可能平移也可能旋转？ | 固定高度前/右平移与倾斜；比较比赛地图与纯色地板 | 计数不是米、SQUAL不是位置精度、需要高度缩放与陀螺补偿 |
| 7 | 三种传感器怎样变成可用控制反馈？ | 检查各有效位；建立IMU矩阵、光流比例/补偿；看虚拟控制器需求 | 通信、质量、时效、标定、任务条件逐层门控；实际PWM始终0 |

### 教师讲解顺序

第1课先摆出三个量：acc是带重力关系的比力，gyro是变化速度，roll/pitch/yaw是估计姿态。平放时有1g而非三个轴都0；没有磁力计时yaw积分仍会漂。NaN与CSV全零初始行含义不同，必须看状态标志。

第2课把通信画为：按键→发射端字节→射频透传→UART中断队列→协议解析→任务请求。先用原厂单字符认识路径，再对比“松手不发包”和“松手仍发心跳”。新包有重复请求，因此任务层要按状态执行，而不是每包重新起飞。原厂Y/Z与新F3降落/F4急停须分开讲。

第3课在VOFA并列显示 requested与actual。先说明哪些条件使请求成为输出，再做无PWM演示。实际电机实验每次只有一只，先验证停机电平/频率再按键，记录位置与旋向。不能用“15%没转”直接判断坏电机。

第4课先画状态机，再从外向内讲控制环：位置→速度→倾角→角速度→混控；高度→垂直速度→基础推力。让队员指出PID中积分饱和保护的目的。最后对照比赛“超过5秒后再一键降落”，说明资格计时与降落命令不是同一事件。

第5课先展示尺子和参考平面，再看状态/距离。距离突然变0不一定是落地，遮挡应使测量无效。低通能降低跳动但不能纠正测量偏差。

第6课先保持姿态做平移，再固定位置做旋转，亲眼确认同样的图像流不能直接当成水平速度。用两个高度的同长度平移解释比例关系。暗光、反光、纯色和运动模糊都要记入实验条件。

第7课逐层检查：原始数据→坐标映射→偏置/质量→时效→估计器→任务状态→虚拟电机。配置开关默认0，必须以实验数据说明可以改为1的理由。本课保留本地按键，不代表无线任务整机已验收。

### 课前基础与材料

C基础薄弱先运行已有`demo00_template`、`demo01_gpio_led`、`demo02_key_led`、`demo05_i2c_scan`。不要按旧环境编号猜源码存在；此次七课用`demo01_vofa`等名称。

备好F22与USB线、VOFA、尺子、比赛地图或纹理纸、外部3.3V USB-TTL（第2课UART4日志）、已确认转接脚序的线束。电机课另外准备符合规格的供电与已拆桨的单路台架。遥控器用USBASP，不用ST-Link或F22串口命令。

授课末尾每组交一张记录表、一段有单位和状态标志的解释、一个编译通过的小改动。可改显示名/绘图/模型目标；控制或输出改动必须重新跑对应测试。某项尚未实测就在记录表写“待到货/待台架”，不能用编译通过代替实测。

## 江西省大学生智能机器人大赛悬停组：规则到实现

依据[比赛实施方案](docs/references/比赛实施方案_2026.7.pdf)，飞行巡航定点赛 V5.0 的第 2、5、6 节。悬停组与巡航组分别排名，我们实现的是悬停组教学链路。

| 原文条款 | 对我们的要求 | 当前 demo 对应 |
|---|---|---|
| 开头与 2.3 | 四轴或六轴；从中心红色圆内起飞 | 机架布局待实物确认；第 4/7 课混控只有虚拟四轴示意 |
| 2.4、2.11 | 无线一键起飞，随后自主，仅降落可继续遥控 | 第 2 课新任务协议只提供起飞/降落/急停/空闲校准；方向键不参与任务控制 |
| 2.7 | 20～100cm 悬停超过5秒，再一键降落 | 目标0.5m，连续稳定时间>5s显示资格标记；达到后继续 HOLD，LAND 指令才降落 |
| 2.9 | 起飞至降落过程无时间限制 | 不设满5秒自动降落 |
| 2.10、3.1 | 落点靠近红圈中心得分更高，中心环500分 | 以起飞点为水平参考，优先减小漂移；光流不识别红圈，不能自动纠正绝对位置 |
| 2.8、3.2 | 标出机身中心，便于裁判读环 | 准备机身中心标记、避开遮挡；直接看清可加20分 |
| 2.12 | 高度不超过1m，约1.5m牵引绳系重物 | 控制器教学模型超1m故障；实飞必须满足绳与重物要求，软件门控不代替物理保护 |
| 6.1 | 带充放电保护的电池，满足动力与载荷 | USB供电仅用于当前传感器教学；动力供电待确认 |
| 6.2 | 在原装传感器基础上可扩展其他无危险传感器 | 4m光流+ToF可作为扩展；保留板载IMU/气压诊断 |
| 6.3、6.4、6.7 | 视觉、动力及控制器需符合原厂要求，动力方式不能改 | 保留F22与原厂动力；暂不增加视觉，不把普通减速电机口M5当旋翼 |
| 6.8 | 也写明可用机载按键起飞，航向必须自主 | 教学第4/7课使用本地按键；正式任务按2.4更具体要求准备无线一键起飞/降落 |

状态机：`IDLE → TAKEOFF → HOLD → LAND → IDLE`；STOP/数据失效的教学门控单独处理。起飞目标缓慢上升到0.5m；HOLD固定起飞点参考；LAND缓降并观察落地。超过5秒只是资格，不是降落命令。即使尚未合格也允许提前降落请求。

模型为稳定计时额外设置高度±5cm、水平半径10cm、垂直速度<0.1m/s、倾角<10°，这是工程演示条件，**不是裁判规则中规定的误差阈值**。实际环尺寸、中心标记、评分与现场组织依原方案和赛事通知执行。

当前完成教学模块与控制器预览，不宣称参赛飞控已完成。实飞前还需：实机电机位置/旋向与混控、传感器安装标定、地面与起飞初段观测策略、真实无线命令接入、更高且稳定的角速度控制周期、PID/悬停油门调参、受控失效降落策略、动力供电验证。光流积分与陀螺yaw均会累计误差；不能因有光流和ToF就认为罗盘问题完全消失。

## 手册梳理与现有硬件

资料索引见 [references](docs/references/README.md)。目前板载IMU/气压已有读数；已买4m模块未到；遥控器烧录器未到；电机实物布局尚未记录。历史自检包含多项诊断，不代表所有功能都完成飞行验收。

| 部件 | 手册要点 / 本工程接口 | 当前证据与用途 |
|---|---|---|
| F22 MCU | STM32F103RC；8MHz晶振，72MHz时钟 | 既有固件运行与串口记录；新教学程序已构建 |
| USB CH340 / 自动ISP | USART1，控制线影响BOOT0/复位 | 既有下载成功记录，也有掉线重枚举；本次无可用端口 |
| E49 / TLE100 | 飞控USART1与USB共用；遥控器AT89S52/11.0592MHz | 原厂字符源码核对；新心跳发射/接收均编译，无线待验收 |
| UART4 JP14 | PC10TX、PC11RX，3.3V | 新遥控日志出口，需独立USB-TTL；不是板载USB日志 |
| MPU6050 | I²C2，7位0x68；±2g/±250°每秒 | 实机读取正常；传感器轴不是已确认的机体轴，姿态控制台架待做 |
| SPL06-001 | I²C2，0x76；出厂系数补偿 | 气压温度能读；相对高度噪声漂移，不能代表离地高度 |
| QMC5883L | I²C2，7位0x0D | 当前板无ACK；其他板同固件有应答。板级通信异常，不足以单独确认芯片本体坏 |
| EEPROM ST24C02 | 地址0x50～0x57取决于跳线 | 历史板3在0x52写读一致；写入会改变内容，不能用来当飞行状态持久化测试 |
| M1～M4 | TIM3重映射PC6～PC9，板载空心杯驱动 | 新单路台架待实测，电机位置/旋向/供电未确认；无需普通无刷ESC信号假设 |
| M6/M7 | TIM4 PB6/PB7，与I²C1冲突 | 六旋翼资源可用但实际布局未确认；不能使用四轴虚拟混控直接驱动 |
| M5 | PA8，减速直流电机用途 | 不属于旋翼教学电机；原全7路自检不能代替单路标定 |
| ADC / DAC | JP8分压输入，PA4/PA5输出 | 历史自检有读取/置码；ADC精度需要已知电压，DAC需要仪表量测，未当作全部性能已验收 |
| GPIO / 按键 / LED | KEY1/2 PC12/13低有效；LED PA0/1 | 已有基础例程；新demo用状态灯与按键门控 |
| ATK-PMW3901 4m | PMW3901 SPI + VL53L1X I²C；模块3.3～4.2V | 已写第5/6课驱动，寄存器替身测试通过；实机识别、测量/标定待到货 |

“SPL06 ID寄存器0x0D”和“QMC5883L器件7位地址0x0D”是两种不同地址，不要混淆。ToF的7位0x29左移后0x52与EEPROM7位0x52也不是同一个地址。

用户原采集文件`data/vofa+.csv`是采集数据；本次教学CSV分别放各课目录并全零初始化。运行中失败会显示NaN或有效位0，不会为了全零模板要求把真实数据也固定为0。

当前优先顺序：先完成板载数据和模型教学→遥控心跳实测→拆桨单路电机记录→ToF与光流到货验证→坐标与比例标定→受控姿态台架→真实任务整合→符合比赛要求的系绳悬停。蜂鸣器与灯声现象应按对应固件/供电单独排查，不能仅凭响声判断IMU故障。

## 第 1 课：VOFA 观察传感器

目标：读懂加速度 g、角速度 °/s、姿态 °，理解 float32 数据帧，观察传感器和姿态模型的关系。

代码入口：`main.c`。环境 `demo01_vofa` 与 `demo_vofa` 使用同一份代码。接板载 CH340 USB，开机将板子静止放置，前约 0.5 s 用于陀螺零偏采样。

```bash
pio run -e demo01_vofa
pio run -e demo01_vofa -t upload
```

VOFA 用 JustFloat、115200、8N1、无流控。运行控制线为 DTR=1、RTS=0；连接后无数据先检查端口、占用和 RESET。20 列全零模板在 [vofa.csv](docs/vofa.csv)，完整通道表和 Cube 四元数绑定见 [VOFA.md](docs/VOFA.md)。

实验：

1. 静止：加速度模长约 1g、角速度接近 0、ImuOK/BaroOK 为 1。
2. 缓慢绕一根轴转动：观察对应 gyro，再看 roll/pitch/yaw 变化；避免超出当前 ±250 °/s 陀螺量程。
3. Cube 绑定 quat_x/y/z/w，模型随板子动；初始显示方向可用位姿偏置调整。
4. 看 CH19 `relative_altitude_m`，解释气压波动与漂移。它经过平滑，但不表示准确离地高度。

提问：板子静止时 acc_z 为什么接近 1 而不是 0？gyro_z 归零后 yaw 为什么不一定归零？平滑高度是否等于提高测距准确度？

本课没有电机输出。CSV 是列名/初始值模板，`vofa+.csv` 是用户采集文件，不能互相覆盖。当前教学验证状态见 [验证记录](docs/LESSON_VALIDATION.md)。

## VOFA+ 实时查看 UAV-F22 传感器

新增独立环境 `demo_vofa`，通过板载 CH340 / USART1 连续发送 20 个通道。
正常循环为 50 Hz，串口 115200、8 数据位、无校验、1 停止位、无硬件流控。
每帧 84 字节，约 4200 字节/秒。原 `demo_selftest` 仍可单独编译、烧录。

### 使用

1. 连接板载 CH340 USB，关闭其他占用该串口的软件。
2. 编译、烧录：

   ```bash
   pio run -e demo_vofa
   pio run -e demo_vofa -t upload
   ```

3. 在 VOFA+ 中选择 CH340 对应的串口，设置 **115200 / 8N1 / 无流控**。
4. 数据引擎选择 **JustFloat**，打开串口。协议来自
   [VOFA+ 官方文档](https://www.vofa.plus/docs/learning/dataengines/justfloat/)：
   小端 float32 数组后追加 `00 00 80 7F`。
5. 添加曲线控件或数值显示控件，绑定下面的通道。建议按加速度、角速度、
   倾角、温度、气压分开显示，避免不同单位挤在同一纵轴。

PIO 对照接收命令（JustFloat 为二进制，用十六进制显示）：

```bash
pio device monitor -e demo_vofa -p /dev/ttyUSB0 -b 115200 --encoding hexlify --dtr 1 --rts 0
```

串口打开后设置控制线；实测仅 USB 供电可读取 IMU 和气压计。

串口控制线使用实机 PIO 监视器确认能接收数据的 **DTR=1、RTS=0**（逻辑状态，对应
PlatformIO 的 `monitor_dtr` / `monitor_rts`，不是引脚电压）。控制线连着
自动 ISP 电路；若 VOFA+ 支持设置 DTR/RTS，请用此设置。打开串口后无输出时，
将 DTR 设为启用、RTS 设为关闭，再按板上复位键。
烧录退出序列的最终状态不能直接当作监视器的运行态设置；本板实测监视器
RTS=1 无连续数据，RTS=0 有连续数据，原来的 monitor_rts=0 已恢复。

实际 Cube 控件显示步骤：拖入 **Cube** 控件，右键切换到**四元数模式**，绑定：
X=`quat_x`（CH15）、Y=`quat_y`（CH16）、Z=`quat_z`（CH17）、Scalar=`quat_w`（CH18）。
当前四元数由陀螺积分加加速度计横滚/俯仰修正得到，启动时静止校准陀螺零偏。
启动校准约 0.5 秒，请将板子平放并保持不动；模型朝向与实物安装方向不一致时，
在 Cube 的位姿偏置窗口里调整初始朝向。VOFA+ Cube 官方说明见
[Cube 控件文档](https://www.vofa.plus/docs/learning/widgets/cube/)。

### 通道表

通道按传输顺序从 0 编号；若界面从 1 编号，则依次加 1。
JustFloat 不发送通道名，请按表手动命名。

| 通道 | 建议名称 | 单位与含义 |
|---|---|---|
| CH0 | AccX | g，传感器 X 轴加速度 |
| CH1 | AccY | g，传感器 Y 轴加速度 |
| CH2 | AccZ | g，传感器 Z 轴加速度 |
| CH3 | GyroX | °/s，已扣除上电静止零偏 |
| CH4 | GyroY | °/s，已扣除上电静止零偏 |
| CH5 | GyroZ | °/s，已扣除上电静止零偏 |
| CH6 | ImuTemp | °C，MPU6050 芯片温度 |
| CH7 | RollDeg | °，融合姿态横滚角 |
| CH8 | PitchDeg | °，融合姿态俯仰角 |
| CH9 | Pressure | hPa，SPL06 出厂系数补偿后的气压 |
| CH10 | BaroTemp | °C，SPL06 出厂系数补偿后的温度 |
| CH11 | ImuOK | 1=本次 IMU 读取成功，0=失败 |
| CH12 | BaroOK | 1=本次气压计读取及补偿成功，0=失败 |
| CH13 | IntervalMs | ms，两帧采样开始时刻间隔，正常约 20 |
| CH14 | YawDeg | °，启动为 0 的相对航向，陀螺积分会漂移 |
| CH15 | QuatX | 四元数 X 分量 |
| CH16 | QuatY | 四元数 Y 分量 |
| CH17 | QuatZ | 四元数 Z 分量 |
| CH18 | QuatW | 四元数标量分量（Cube Scalar） |
| CH19 | RelativeAltitude | m，SPL06 气压换算并经低通平滑的相对高度，首次有效气压设为 0 |

IMU 加速度量程 ±2g，换算 `raw/16384`；角速度量程 ±250°/s，换算 `raw/131`。
MPU6050 温度按 `raw/340+36.53`，依据
[TDK/InvenSense 寄存器手册](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6000-Register-Map1.pdf)。
SPL06 系数和补偿公式依据本地厂家 `SPL06_001.c`，压力与温度过采样分别为
32 倍、8 倍，缩放系数分别为 516096、7864320。

### 看数据时怎么判断

- 静止时加速度模长应接近 1g，角速度应接近 0；转动时角速度曲线会变化。
- 横滚/俯仰由陀螺积分并由加速度计在接近 1g 时修正；快速平移和振动仍会影响姿态。
  姿态以传感器坐标系为准，尚未按机体安装方向变换。
- Yaw 从启动时置零后由陀螺积分，没有磁力计纠偏，会随时间漂移。
- `RelativeAltitude` 由气压相对开机参考值换算，并做轻度低通平滑以减小显示跳动；平滑会带来少量延迟，但不会提升测量准确度。气压噪声、温漂、螺旋桨下洗和天气变化都会造成明显误差，不能当作离地高度或用于低空定高控制。等待 ToF 到货并装好后，应使用它测量飞机到地面的距离。
- 每次启动用约 0.5 秒的静止采样估计陀螺零偏，校准期间暂不发送数据。
- 50 Hz 是发送频率，气压计温度配置为 4 Hz，因此温度值连续多帧相同正常。
  有效标志代表通信成功，不表示每帧都是新转换，也不保证硬件读数准确。
- 读取失败时，对应测量通道发送 NaN，状态通道为 0，避免用旧值冒充当前值。
  失败的传感器每秒重试初始化；错误和重试可能使帧间隔超过 20 ms。
  气压计初始化后会等待首次压力和温度就绪，最长 500 ms。
- LED1 指示读取/发送错误，LED2 每 500 ms 翻转表示循环运行。
- 本例程不启动电机 PWM、不执行 EEPROM 自检写入；按键不会触发电机测试。

JustFloat 是二进制数据，普通文本串口窗口显示乱码属于正常现象。
不要把自检的文本输出当作 JustFloat 数据流。

若 CH340 掉线，重新选择实际端口并连接；设备号可能变化。
若本机没有串口设备，只能先编译，烧录和 VOFA+ 曲线需要接板后验证。

## 第 2 课：遥控器字符接收

目标：把串口字节封装成可解释的按键状态，处理无效输入、过期和接收错误。本课所有按键只显示，不控制电机。

代码：`main.c` 负责外设/接收队列；`src/flight/remote.c` 负责纯解析。来自本地 TLE100 `ex3.c` 的协议是 9600 / 8N1，按住键约每 20 ms 重发一次，松手不发送释放包或心跳。

| 字符 | 按键含义 | 解析字段 |
|---|---|---|
| F / B | 前 / 后 | forward=+1 / -1 |
| R / L | 右 / 左 | right=+1 / -1 |
| U / D | 加 / 减 | vertical=+1 / -1 |
| W | F1 | 校准请求 |
| X | F2 | 启动请求，演示程序不会解锁 |
| Y / Z | F3 / F4 | 停止请求 |

每次记录最后一个合法字符；多键同时按住时也只展示最后收到的键，不是完整摇杆状态。250 ms 无合法键则方向/请求归零。`recent=0` 表示近期没按键，不能区分“松手”和“射频断链”。本工程也提供带心跳、序号和 CRC 的任务协议，见下方新版本；原厂字符版继续用于入门。

硬件：板载 E49 的 M0=PA6、M1=PA7 置 0 为透传；UART 接 USART1（PA9/PA10），与 CH340 共用。接收 LED1 在合法键活动窗口点亮；LED2 每 500 ms 翻转。飞控 USART1 不发送调试文字。

详细日志输出到 UART4 / JP14：PC10 TX 接外部 **3.3 V USB-TTL 的 RX**，共地；用 115200 文本串口查看，不需要接适配器 TX。板载 USB 只负责下载，不能从它看到本课的 UART4 日志。不要在射频接收时同时从 CH340 发字节到共用 RX 线。

```bash
pio run -e demo02_remote
pio run -e demo02_remote -t upload
```

验收：每个键收到对应字符，松手后约 250 ms 指令归零；W/X/Y/Z 不会转电机。UART 错误/队列溢出会清空解析状态并重启接收，`err` 增加。实际无线频率、地址和信道还需两端匹配；解析通过不代表射频链路已验证。

练习：画出“按下 → 无线透传 → 中断队列 → 解析 → 活动过期”的过程；说明为什么飞行中不能把本协议的 `recent` 直接当作失联停机判断。

### 第二阶段：带心跳的任务协议

先分别烧录 [TLE100 新发射端](remote/tle100/README.md) 和 `demo02_remote_framed` 接收端；不能只换一边。射频配置仍需一致。

```bash
pio run -e demo02_remote_framed
pio run -e demo02_remote_framed -t upload
```

UART4 日志：`packet_cmd=0/1/2/3/4` 分别是心跳/起飞请求/降落请求/急停请求/校准请求；`link=1` 表示 300 ms 内收到了合法且更新的序号。`seq` 是 8 位循环序号，`frames` 是有效包数；坏校验、旧序号、重复序号不延长链路有效时间。CRC 检查传输错误，不提供身份认证。

LED1 在周期心跳有效时亮；松开全部按钮仍然亮，关闭遥控器后约 300 ms 灭。帧长 6 字节，字节间隔超过 30 ms 清空半帧；队列故障清空链路状态。细节见 [协议说明](docs/RADIO_PROTOCOL.md)。

这一版同样只接收和显示，未连接电机或飞行状态机。不要把原字符版中的 Y/Z 停机含义套到新协议：新协议 F3=LAND，F4=STOP。下一阶段整机接入任务协议时，START/LAND 必须由状态机幂等处理，校准只能在空闲且静止时执行；飞行期间忽略方向键。

验收练习：观察空闲心跳；断电看超时；向主机测试加入错误 CRC/重复包/序号回绕；解释“有字节”和“链路有效”的区别。

## 遥控协议

## TLE100 任务协议 v1

该协议用于新发射端 `remote/tle100/main.c` 与飞控 `demo02_remote_framed`；原厂字符协议另见第2课。发射端 AT89S52 / 11.0592MHz / 9600 8N1，E49透传，两端频率、地址、信道及 UART 配置须一致。

| 偏移 | 字段 | 值 |
|---|---|---|
| 0、1 | 帧头 | A5 5A |
| 2 | 协议版本 | 01 |
| 3 | 序号 | 每包加1，255回到0 |
| 4 | 命令 | 0心跳、1起飞、2降落、3急停、4校准 |
| 5 | CRC8 | 覆盖前5字节；多项式0x07、初值0、不反射、无末尾异或 |

不按键也发心跳。Timer0等待20ms，加上6字节UART传输约6.25ms，实际周期约26ms；实机需测量。按键用两次扫描确认，F2/F3/F1新按下边沿分别发START/LAND/CALIBRATE，并重复3个新序号包约79ms；按住F4重复STOP，优先级最高，其次LAND、START、CALIBRATE。上电已经按住的START不算新边沿，必须释放后再按。

接收器滑动窗口找6字节帧，坏校验/错误版本/未知命令不更新链路；同一有效链路期间序号仅接受向前1～127步，重复或过旧包不更新。字节间隔>30ms丢掉半帧，300ms没有新有效包则链路无效。断链后第一包可重新建立序号基准，所以两端重启/长时间断线可恢复。CRC用于误码检测，不是密码学验证。

命令包重复不应重复执行任务：START只在空闲且传感器、供电、坐标与任务条件合格时起效；LAND在起飞/悬停时进入降落；STOP清空台架输出；CALIBRATE仅空闲且静止才可执行。第2课只是日志验证器，尚未接入第7课。接入实际飞控后，不能将“某包没收到”直接做无条件空中停桨；须按传感器剩余可用性设计并验证失联降落策略。

飞行期间不发送航向/方向操纵，因此符合自主任务目标。没有完整手动摇杆功能，也没有ACK确认显示；请求重复3次只能改善瞬时丢包，不能证明任务已经被接收执行。验收要同时观察接收日志与任务状态。

## 第 3 课：电机输出门控

目标：观察“请求占空比”和“实际占空比”的区别，学会一次测试一个电机。

默认环境 `demo03_motor` 不初始化 PWM，物理输出始终为 0。先烧此环境学习门控：

```bash
pio run -e demo03_motor
pio run -e demo03_motor -t upload
```

VOFA：JustFloat / 115200 / DTR=1 / RTS=0，10 Hz，通道表见 [vofa.csv](src/demo/demo03_motor/vofa.csv)。状态 0=等按键释放，1=空闲，2=长按计时，3=运行窗口。必须先松开两键；长按 KEY1 满 2 s 后请求 15%，最多 3 s；松手或按 KEY2 则归零，重新松开后才能再次触发。门控输入每约 10 ms 检查，串口超时可能让停机判断多等待一个循环。

### 拆桨单电机台架

确认桨叶已拆、供电符合电机规格，先确认零占空比与 PWM 极性后，使用 `demo03_motor_bench`。它只启动编译时选择的一路 PWM，其余通道不启动。

```bash
pio run -e demo03_motor_bench
pio run -e demo03_motor_bench -t upload
```

默认 `MOTOR_TEST_INDEX=1`（M1 / PC6 / TIM3_CH1），修改 `platformio.ini` 可选择 1/2/3/4/6/7；M5 禁止用于本课。台架环境把 TIM3/TIM4 的 ARR 设为 66，1 MHz 计数时实际周期 67 µs，约 14.9 kHz。其他旧环境的周期设置不变。

台架版启动独立看门狗，名义超时约 0.5 s（LSI 频率有偏差），主循环停止喂狗时触发复位。实际停机电平、波形、看门狗复位后的电机响应和限流都必须实机验收；编译/主机测试不能证明这些硬件行为。

验收：上电不转、上电按住 KEY1 也不转；释放后按流程运行，只选中电机有输出；松手/KEY2/3 s 超时停转；连续按住不重复启动。15% 可能不足以克服启动摩擦，不能据此判断电机损坏，也不要直接提高到大油门。

练习：解释为何不允许测试 M5；为什么 M6/M7 与 I2C1 冲突；把状态机画出来并标明每条停机路径。

占空比列表示程序请求/应用给驱动API的百分比，不是示波器测量值。ARR=66时只有67个计数档，15%会有量化误差，当前既有驱动写CCR=9；低有效PWM的驱动有效时间约9/67=13.4%，验收应按实测波形记录。

## 第4课：悬停逻辑

## 第 4 课：悬停逻辑软件演示

目标：先看懂状态机和控制层次。这个 demo 的高度、位置、姿态全部来自理想软件模型；四路电机是虚拟需求，物理 PWM 不启动。

```bash
pio run -e demo04_hover_logic
pio run -e demo04_hover_logic -t upload
```

VOFA：JustFloat / 115200 / DTR=1 / RTS=0，约 50 Hz。模板 [vofa.csv](src/demo/demo04_hover_logic/vofa.csv) 有 20 列，初始全 0。`actual_pwm` 恒为 0，`input_simulated` 恒为 1。

启动后空闲；松开 KEY1 再按一下，软件模型开始起飞，目标高度逐步升到 0.5 m；高度/位置/姿态满足演示条件时累计稳定时间，超过 5 s 后继续保持，等待你松开再按 KEY1 发出降落请求。降落时目标高度逐步降到 0，模型落地停机。可以提前请求降落，但不满足比赛的悬停时长。KEY2 立即停止虚拟输出。停止时如果模型还在空中，它会模拟下落，落回地面后才能再次启动。

状态：0=IDLE，1=TAKEOFF，2=HOLD，3=LAND，4=FAULT。高度/位置/IMU/命令链路无效、非有限值、大倾角、超高或错误 dt 会锁存 FAULT 并清空虚拟输出；先 STOP 再 START 才能恢复。本例故障停输出是模型/台架门控演示，真实飞行的失效降落策略还需独立设计与验证。

控制层次：

1. 位置误差生成水平速度目标，速度误差生成 roll/pitch 目标。
2. 角度外环生成角速度目标，陀螺角速度内环 PID 生成三个轴的修正量。
3. 高度误差生成垂直速度目标，垂直速度 PI 修正基础推力。
4. 虚拟四旋翼混控把基础推力和修正量分配给前左/前右/后右/后左。

PID 有积分限幅、输出饱和时停止继续积分、测量微分与微分低通；混控会压缩超范围差动量并移动共同推力，使虚拟电机落在 0~1。

| CH | 数据 |
|---|---|
| 0 | state |
| 1 / 2 / 3 | height_m / height_target_m / vertical_speed_mps |
| 4 / 5 | roll_deg / pitch_deg |
| 6 / 7 | x_m / y_m |
| 8 / 9 | vx_mps / vy_mps |
| 10 | collective，归一化基础推力 |
| 11 / 12 / 13 | roll / pitch / yaw correction |
| 14 / 15 / 16 / 17 | virtual_FL / FR / RR / RL |
| 18 / 19 | actual_pwm=0 / input_simulated=1 |

注意：本课没有使用真实 SPL06 高度。0.45 基础推力、PID 参数、50 Hz 模型周期和四旋翼顺序仅供讲解，不能套到未知机架。真实输入还需轴变换、时间戳、ToF/光流驱动、速度估计、遥控心跳、机架与电机旋向确认，并完成实机调参。

练习：将模型目标高度改为 0.4 m，观察起飞/保持/降落；在主机测试里让 height_valid=0，说明为什么进入 FAULT；指出气压计数据平滑为何不能代替可靠测距。

比赛流程与评分对应见 [规则映射](docs/COMPETITION.md)。本课持续保持时可以看 `controller.stable_seconds`；整合课将此数值和资格标记独立发送。

## 第 5 课：VL53L1X 测距

目标：用激光飞行时间测量传感器到地面的距离，区分“芯片识别成功”“一次测量有效”“数据仍然新鲜”。本课使用已购买的正点原子 ATK-PMW3901 **4m** 模块中的 VL53L1X，不能换成 2m 版 VL53L0X 驱动。

前置：第 1 课 VOFA、I²C 地址与 7/8 位地址区别。先读 [模块转接接线](docs/MODULE_WIRING.md)，模块原手册保存在 [参考目录](docs/references/README.md)。算法入口是 `src/sensors/tof.c`，F22 硬件适配在 `src/sensors/f22_sensor_bus.c`，高度滤波在 `src/flight/observation.c`。

```bash
pio run -e demo05_tof
```

实验：模块水平向下，对准有纹理的平地，用尺子设置 0.2、0.5、0.8 m，各静置 10 s；记录均值、波动范围、有效率和更新间隔。遮住测距窗口、远离量程后观察 `tof_valid=0`；有效距离/滤波高度显示 NaN，而不是伪造零高度。数据超过 150 ms 不再有效；超过 500 ms 没新结果则重新初始化，重试间隔约 2 s。

原始距离从**传感器测量平面**算起，不是飞机机身中心。倾斜时读到斜距，本课没有 IMU，因此 CH2/3 只适合水平台架；第 7 课用姿态估计做 `distance*cos(roll)*cos(pitch)` 投影。传感器安装偏移、覆盖片串扰与零点偏差仍需尺子实验校准。速度来自低通高度的差分，响应有延迟；尚未与惯性加速度融合。

常见错误：把 0x29 写成 HAL 传输参数而不左移；用 8 位寄存器地址（该芯片要求 16 位）；没接模块使能造成内部地悬空；只看旧距离而忽略有效位；以为 4m 是在任意强光下都保证测准。解决方法先对照接线和状态，再用尺子复测。

练习：为什么距离增长对应向上速度？为什么遮挡不能被当作已落地？用主机测试解释通信失败与非有效测距状态的不同路径。

验证状态：已编译；替身寄存器测试覆盖型号、字节序、错误、超时和计时回绕；模块未到货，实机测距未验收。全程没有 PWM。

## 第6课：光流

## 第 6 课：PMW3901 光流

目标：先读懂地面图像运动量和质量，再学习为什么要用高度缩放、陀螺旋转补偿。光流给的是运动增量，不会直接识别地图红色圆环，也不会输出绝对航向或绝对位置。

前置：第 5 课可靠测距；阅读 [模块接线](docs/MODULE_WIRING.md)。入口 `src/sensors/flow.c`；初始化配置采用 Bitcraze MIT 驱动寄存器序列，来源与许可证见 [参考资料](docs/references/README.md)。SPI2 为模式 3、MSB first、1.125 MHz；片选 PB12；12 字节 Motion Burst 一次读取同组结果。

```bash
pio run -e demo06_flow
pio run -e demo06_flow -t upload
```

VOFA JustFloat / 115200 / DTR=1 / RTS=0，约 50 Hz；导入 [vofa.csv](src/demo/demo06_flow/vofa.csv)，16 列，初始全 0。

| CH | 名称 | 含义 |
|---|---|---|
| 0 / 1 / 2 | flow_present / flow_id / flow_inverse_id | 初始化成功 / 0x49=73 / 0xB6=182 |
| 3 / 4 | delta_x_counts / delta_y_counts | 本轮传感器 X/Y 图像位移计数，带正负号 |
| 5 / 6 / 7 | squal / motion_flags / flow_valid | 图像特征质量 / 原始标志 / 本例质量通过 |
| 8 / 9 | sum_x_counts / sum_y_counts | 有效计数累计；KEY1 清零 |
| 10 / 11 | distance_m / tof_valid | ToF 有效距离 / 标志 |
| 12 / 13 | flow_errors / tof_errors | 当前初始化周期内错误次数 |
| 14 / 15 | velocity_calibrated / actual_pwm | 均恒 0；本课没有校准后的速度输出或 PWM |

先静置模块于地面上方 0.5 m，记录 SQUAL；再保持高度与姿态，用尺子向前/右各移 0.2 m，观察 dx/dy 对应哪一个轴、正负号和累计计数。重复往返，检查返回原处后累计漂移。再固定位置慢慢倾斜，观察旋转也会制造图像运动。最后对比纹理纸、比赛地图哑光面、纯色地板与光滑反光面。

`flow_valid` 只说明本次读数通过起始 SQUAL>=15 阈值，不表示已经得到可用于飞行的位置。静止时 motion 的最高位可以为 0，不能因此认为传感器坏了；bit4 是 rawFrom0 标志，不能当作溢出。通信失败会清空本轮增量，初始化失败约 2 s 后重试。低质量的原始增量仍可观察，但不计入累计量。

换算思路：`位移≈高度×图像角度`；图像角度先由计数乘标定比例，再扣掉陀螺估计的旋转贡献，除以真实时间间隔得到速度。厂家示例给出初始比例约 0.002131946 rad/count，镜头批次、安装方向、地面和时序都会影响结果，必须实测标定。第 7 课默认禁止输出有效水平速度，直到你填写标定值。

常见错误：贴地测试（光流工作距离需大于约 8 cm）；暗处或纯色地面看不到特征；把计数当成毫米；旋转当平移；未经轴映射就反馈到电机；没有 ToF 还相信光流米制速度。先完成尺子和平移/倾斜实验再继续。

练习：同样移 20 cm，在 0.3/0.6 m 高度上累计计数会怎样变化？静止倾斜为什么要补偿？坏质量期间丢失的位移能否靠下一帧自动恢复？

验证状态：已编译；替身 SPI 测试覆盖 ID、负数解码、质量判断和通信故障；硬件未到，实机与比例未验收。

## 光流与ToF接线

## 已购 4m 模块与 F22 转接

[正点原子原手册](docs/references/ATK-PMW3901-manual.pdf) PDF 第 3 页列出参数，第 5 页图 2.1.4 给出电路。4m 版是 **PMW3901 + VL53L1X**，同一个板上已有光流和 ToF；没有输出定位数据的串口 MCU。2m 版才用 VL53L0X。

手册中的 PA8、PB4、PB5 是 **MiniFly 的引脚**，不是必须在 F22 上使用这些引脚。F22 使用硬件 SPI2、I²C2 和一个使能 GPIO 转接，下面号码按手册 HEAD1/HEAD2 标注。照片不能确定排母翻面后的脚序；收到后对照丝印、方形焊盘及通断测量核对 1 脚，再接线，不能凭左右位置插到 F22。

| 模块手册端子 | 信号 | F22 连接 |
|---|---|---|
| HEAD1-1 | GND | F22 GND |
| HEAD1-8 | +BATT，模块电源输入 | 稳定 3.3 V（JP10 电源），先验证模块输入和 LDO 输出 |
| HEAD2-2 | E_CS1 / PB0，模块内部地开关使能 | F22 PC14（J2 对应 PC14），程序拉高使能 |
| HEAD2-4 | E_CS3 / PA8，PMW3901 NCS | PB12 / JP5 NSS，软件片选 |
| HEAD2-8 | E_SCK / PB13 | PB13 / JP5 SCK |
| HEAD2-7 | E_MISO / PB14 | PB14 / JP5 MISO |
| HEAD2-6 | E_MOSI / PB15 | PB15 / JP5 MOSI |
| HEAD1-4 | E_SCL / PB5，ToF 时钟 | PB10 / JP7 SCL2 |
| HEAD1-3 | E_SDA / PB4，ToF 数据 | PB11 / JP7 SDA2 |

未使用端子保持不接，包括 VUSB、串口标记端子、ADC 模块识别脚、备用 CS。默认 L2 焊接时，HEAD2-1 的 VCC3.0 不是本方案必接的电源输入；必须检查实际板的 L1/L2 焊接状态。另一个与 E_CS3 同网的端子不需重复接。XSHUT 在模块内部上拉，程序通过总线初始化，不另引出复位脚。

供电范围为模块整体 **3.3～4.2 V**，手册标称约 20 mA；不能把 JP9 的 5 V 当作该模块电源。F22 IO 使用 3.3 V，模块内 LDO 产生约 3.0 V 的 VDDIO；先检查实际电平与上拉、供电压降和公共地。芯片裸 VDD 的 1.8 V 规格不是模块端口供电规格。我们的 PC14 高电平仅控制使能，不能从 GPIO 给模块直接供电。

总线：I²C2 保持 100 kHz，与 MPU6050(0x68)、SPL06(0x76) 共线，ToF 为 7 位 0x29，HAL 参数左移后为 0x52；ST24C02 的 7 位 0x52 若在另一条扫描记录中出现，不能混为同一器件。ToF 内部寄存器地址是 16 位。SPI2 36 MHz/32=1.125 MHz，模式 3、软件 CS；避免超过 PMW3901 手册的 2 MHz。

不使用 I²C1/PB6/PB7，以免与六旋翼的 M6/M7 冲突；不复用 PA8，避免占用 M5。F22 的扩展口与 MiniFly 的 2×8 排针脚序不同，不可直接整排对插。

安装方向：光流与测距窗口朝地，模块箭头对机头作为初始约定，再用平移试验确认轴映射。传感器视野不要被脚架、绑带遮住。测距从传感器平面起算，标记安装偏移；悬停20～100cm范围满足光流大于8cm的工作距离，落地初段仍需专门处理。

到货验收按第 5/6 课执行，记录距离尺测、质量、光照、地面纹理和时间间隔。此表来自原手册与 F22 引脚定义，当前尚无实际接线验证。

## 第7课：整机联调

## 第 7 课：真实传感器与悬停控制器联调

目标：把真实 IMU、ToF、光流读数接到同一个数据链路，逐层检查有效位和控制器需求。**实际电机 PWM 恒为 0，源码没有飞行输出开关。**本课是联调和教学程序，不能作为实飞固件。

前置：第 1～6 课；模块连接见 [接线表](docs/MODULE_WIRING.md)，任务规则见 [比赛映射](docs/COMPETITION.md)。入口 `main.c`；姿态/高度/速度数学在 `src/flight/observation.c`，控制器在 `src/flight/hover.c`。

```bash
pio run -e demo07_integration
pio run -e demo07_integration -t upload
```

上电静置约 0.5 s。只有加速度模长约 0.9～1.1g 且所有陀螺轴绝对值小于 2°/s 才接受零偏校准，失败会重试。六轴四元数滤波通过加速度修正倾角，yaw 仍是相对角并会漂移。此课 50 Hz 遥测与控制预览用于观察，真实角速度内环需要后续测量更高且稳定的周期。

### 标定与开关

[config.h](src/demo/demo07_integration/config.h) 默认 `IMU_MOUNT_VERIFIED=0`、`FLOW_CALIBRATED=0`。所以即使三个传感器都有数，START 也会进入 FAULT，虚拟电机需求为零；这是“硬件通信正常”和“飞行坐标可用”的区别。

先验证 `imu_mount` 3×3 矩阵：机头前、机体右、机体下为机体 X/Y/Z，按右手规则旋转，检查各陀螺和姿态正负号。矩阵须是正确旋转矩阵，不能只改某一个轴产生镜像。MPU6050 加速度读数是比力，平放时具体符号取决于安装；本课采用前/右/下的右手坐标系，平放静止时加速度比力 accZ=-1g；算法内部取负号恢复重力方向。必须确认此参考与实际轴映射匹配，第 1 课的传感器原坐标不能直接冒充机体轴。

光流标定先用已知平移与高度求 `radians_per_count` 和 `translation` 的轴交换/符号，再固定传感器位置逐轴倾斜，用图像角度与陀螺积分拟合 `rotation` 2×2 系数；重复验证残余速度接近零。默认 rotation 全 0 未补偿，只能用于讲解数据路径，不能直接把标志改成 1 后飞。水平速度超过 2 m/s、dt 不合理或高度小于 8 cm 时估计无效。

距离向上投影使用 roll/pitch，倾角超过 30° 拒绝；150 ms 过期或通信失败会使高度无效。光流积分位置只在有效区间累加，坏数据期间的位移丢失且无法补回，因此重新获得质量后位置可能不连续。这是台架联调限制，真正飞行需状态估计、丢测处理与重新建立参考。

### 按键与通道

KEY1 的新按下边沿：空闲时 START，运行时 LAND；KEY2 STOP。本课只用板载按键，`local_button_input=1`；`command_link_valid` 表示这条本地试验输入，未接无线心跳。第 2 课新协议还需另行接入整机任务层。

导入 [vofa.csv](src/demo/demo07_integration/vofa.csv)，28 列，初始全 0；VOFA JustFloat / 115200 / DTR=1 / RTS=0，约 50 Hz。

|---|---|
| 0 | state：0空闲 / 1起飞 / 2保持 / 3降落 / 4故障 |
| 1 / 2 / 3 | roll_deg / pitch_deg / yaw_relative_deg |
| 4 / 5 | height_m / vz_mps：向上为正 |
| 6 / 7 / 8 / 9 | x_m / y_m / vx_mps / vy_mps：本地起飞航向参考，未标定时 NaN |
| 10 / 11 / 12 | 光流 dx / dy / SQUAL |
| 13 / 14 / 15 | IMU 通信正常 / ToF 测量有效 / 光流质量有效 |

验证状态：构建和主机数学/控制器测试通过；实机模块、轴映射、姿态台架、无线任务联调与悬停尚未验收。
